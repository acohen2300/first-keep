# The mockup format: pictures before code [2026-11-01 07:45]

How a screen is drawn and agreed, as done for v70 and v80. [2026-11-01 07:45]

1. **Draw it on the mold.** Every picture is on the grid of `docs/2 Rules/MENU-SPEC.md` (the Formation: six slots of 58 by 44 at 390, gaps of 6), in the named colours of `docs/2 Rules/COLORS.md`, with the two text sizes and two fonts (D-044, D-046). [2026-11-01 07:45]
2. **Show the choices side by side.** Where there is a choice, draw each option as its own picture (for example `Weights A and B`, `Setup Singles` against `Setup Stacked`, `Start 900 Against 600`), so Albert picks by looking. [2026-11-01 07:45]
3. **Name and file it.** One PNG per picture, in `mockups/vNN/`, named `<What it shows> - vNN - <session name>.png` (for example `mockups/80/Relations Final - v80 - Post Clean - Working.png`). [2026-11-01 07:45]
4. **Write the decision with the picture.** Each agreed item names its pictures at the end: "Picture: Relations Final." It records Albert's words and the time: "(Albert, Oct 31, 10:16–10:18, "we are locking into the final")". [2026-11-01 07:45]
5. **Lock it.** The agreed item becomes a decision file in `docs/3 Locks/Decisions/`, and the screen gets (or updates) its design file in `docs/3 Locks/Designs/`, linking the picture and the MENU-SPEC section. [2026-11-01 07:45]
6. **Then build.** The builder builds to the picture; the gate measures the card at four phone sizes. [2026-11-01 07:45]
